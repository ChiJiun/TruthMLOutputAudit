% 摘要
\begin{abstract}
聯邦學習可讓多個客戶端在不直接共享原始資料的情況下共同訓練模型，但伺服器通常仍需相信客戶端已正確執行差分隱私更新，例如更新裁剪與雜訊注入。此信任假設使得差分隱私流程缺乏可審計性。本研究依據三階段計畫建構可驗證差分隱私聯邦學習原型：首先建立聯邦學習基準流程；接著加入差分隱私更新器；最後將差分隱私更新中的核心條件轉換為可由 ZKML/EZKL 驗證的約束條件。實驗結果顯示，推薦約束條件設定可使誠實設定檔以 9/9 通過，篡改設定檔以 18/18 被拒絕；實際 EZKL 約束條件證明展示中，誠實案例通過驗證，而篡改含雜訊更新的案例因關係檢查失敗而被拒絕。進一步地，驗證後聚合在一輪端到端實驗中接受 2/3 個客戶端並拒絕篡改客戶端，模型準確率從 0.694851 提升至 0.839697。跨資料集實驗最終涵蓋 16 個資料集；其中 Forest CoverType 有 581,012 筆，完整 training split 的 FL／clipping-only／DP-update final accuracy 為 0.719890／0.700633／0.636799，單次訓練約 51--52 秒、peak RSS 約 716 MiB。其 385 維完整更新亦完成 actual EZKL，honest case 被接受、tampered noisy update 被拒絕。三資料集、三 seeds 的成本實驗中 9/9 honest runs 通過，平均 proving time 為 0.100--0.586 秒，peak RSS 為 410.0--426.0 MiB，proof size 約 11.9--12.3 KB。CoverType non-IID/client scaling 另完成 K=3/10、三種 partition、5 seeds 共 90 runs；多輪 threat matrix 完成 48 條 trajectories 與 1,440 次 client 決策，current gate 對 relation/clip 違規接受率為 0\%，但 replay/zero-noise 為 100\%，加入 context/randomness policy 後可降為 0\%。Bounded sign-flip 仍以 100\% 通過，顯示 update audit 不等於完整 local-training proof。最後，RDP accountant 顯示現行 public deterministic seed 讓 verifier 可重建 noise，故實際 privacy budget 為 $\epsilon=\infty$；即使假設秘密 Gaussian noise，10 輪、replace-one、$\delta=10^{-5}$ 下的原設定亦為 $\epsilon=3504.357$。因此本研究證明的是 ZKML 可審計 DP-update 原型的可行性，而非已完成有限 privacy budget 或任意 poisoning defense 的部署系統。
\end{abstract}

% (一) 緒論
\section{緒論}

聯邦學習（Federated Learning, FL）將模型訓練分散於多個客戶端，使客戶端可保留原始資料並僅提交模型更新。此設計降低了資料集中化風險，但並不等於完整隱私保護，因為模型更新本身仍可能洩漏資料特徵。差分隱私（Differential Privacy, DP）常被用於緩解此問題，其核心流程通常包含更新裁剪（clipping）與雜訊注入（noise injection）。然而，在一般 FL+DP 流程中，伺服器往往只能相信客戶端已正確執行 DP 更新，無法直接驗證其是否真的依照規則完成裁剪與加噪。

若用較直觀的比喻說明，傳統 FL+DP 像是多個客戶端把「已模糊處理過的模型更新包裹」交給伺服器，但伺服器只能相信包裹真的依規定先裁剪、再加噪；本研究希望讓每個包裹都附上一張不洩漏內容的「數學收據」，使伺服器能確認包裹符合 DP 處理規則，再決定是否納入聚合。

本研究的核心問題是：\textbf{差分隱私更新是否能被轉換成可驗證的約束條件，並在不揭露客戶端資料的前提下由 ZKML 進行審計？}此問題對應計畫書中的三個系統層級：S0 為 FL 基準實驗，S1 為 FL+DP，S2 為 FL+DP+ZK 驗證。與完整將整個本地訓練流程寫入單一 ZKML 電路不同，本研究採取較務實的切入點：本地訓練仍在客戶端完成，而 ZKML 聚焦驗證 DP 更新中的關鍵條件。

本文依照 REL 規則組織論述：每個主張均對應實驗數據或形式化定義；基準實驗的限制被明確指出；方法流程依序拆成資料、FL、DP、VDP 約束條件與驗證後聚合；最後再討論限制與未來補償方向。本文貢獻如下：

需要先界定本文的貢獻邊界：本文不宣稱提出新的 DP optimizer、ZKP protocol 或底層 proof system。研究的新意定位於方法工程與系統實證，即如何把 DP 更新重構為可穩定量化的見證與約束、如何讓驗證結果直接控制聚合，以及如何用 honest/tampered cases 與成本指標評估此審計介面。

\begin{itemize}
    \item 建立 UCI Adult Income 上的 FL、DP 與 ZKML 原型流程，對應計畫書中的 S0、S1 與 S2。
    \item 將差分隱私更新中的裁剪與雜訊關係形式化為可驗證約束條件。
    \item 提出標準化量化見證與固定容差策略，以處理量化後的捨入問題。
    \item 以 EZKL 實際驗證推薦約束條件，並完成驗證後聚合與端到端單輪結果。
    \item 於 16 個資料集上進行重複實驗，並以 581,012 筆 Forest CoverType 檢查大型樣本規模下的 FL／clipping-only／DP-update utility、時間與記憶體。
    \item 於 Iris、Wine 與 Digits 多類別資料集上驗證完整 DP 更新向量，並量測不同模型維度下的 EZKL proof size、proving/verification time、peak RSS、key size 與 application-layer payload。
    \item 建立 client-level Gaussian RDP accountant 與 privacy--utility frontier，並辨識 public deterministic seed 使現行機制不具有限 privacy budget 的關鍵限制。
    \item 以 CoverType K=3/10、IID/Dirichlet partition 與多輪攻擊矩陣量測 client heterogeneity、惡意接受率及安全拒絕的 utility/availability 代價。
    \item 對核心 raw results 執行完整性、paired effect、exact permutation、Holm correction、環境版本與 SHA-256 稽核，明確限制小 seed 數的統計解讀。
\end{itemize}

% (二) 文獻回顧
\section{文獻回顧}

聯邦學習的基本目標是在不集中原始資料的情況下訓練全域模型。McMahan 等人提出的 FedAvg 是常見基準方法，其優點是簡潔且易於實作 \cite{mcmahan2017}，但其限制是伺服器通常無法驗證客戶端更新是否依規則產生。更重要的是，FL 並不等於資料完全不會洩漏；Zhu 等人的 Deep Leakage from Gradients 顯示，梯度資訊本身可能被用於重建訓練資料 \cite{zhu2019dlg}，Geiping 等人也進一步指出，在部分設定下僅共享梯度仍可能造成嚴重隱私風險 \cite{geiping2020inverting}。因此，若把 FL 比喻成「資料不離開手機或醫院」，模型更新仍像是從資料中擠出的摘要，摘要本身仍可能透露原始資料的輪廓。

差分隱私則透過限制敏感度與加入隨機雜訊提供統計隱私保護，例如 Dwork 的差分隱私定義 \cite{dwork2006} 與 Abadi 等人的 DP-SGD \cite{abadi2016}。安全聚合也可降低伺服器直接取得個別更新的風險 \cite{bonawitz2017}。然而，傳統 DP 流程仍面臨一個問題：即使演算法描述包含裁剪與雜訊，伺服器仍不一定能確認每個客戶端實際提交的更新符合這些條件。Nasr 等人的 DP auditing 研究也說明，DP 系統需要被檢查與審計，因為實作錯誤或參數設定不當可能讓理論保證與實際行為產生落差 \cite{nasr2023tight}。本研究延續此問題意識，但將焦點放在 FL client update 的「每一筆 DP 更新是否可被驗證」。

Verifiable DP 的關鍵困難是 verifier 必須確認 randomizer 正確，卻不能因此取得可扣除的 noise。Biswas 與 Cormode 以 private/public randomness 的組合建立可驗證 DP counting \cite{biswas2023}；Bontekoe 等人進一步在 local/shuffle model 中處理 input authenticity 與 malicious-client manipulation，並提供形式化安全與可重現 artifact \cite{bontekoe2025}。近期 V$\epsilon$rity 也把 randomizer tampering、dropout 與 input authenticity 明確納入威脅模型，使用共同衍生的 PRF randomness 與證明機制 \cite{bellclark2026}。這些工作顯示，只驗證 additive relation 或隱藏 JSON seed 都不足以構成投稿等級的 verifiable randomness；本文因此將 public-seed 負面結果與 context-bound hidden-randomness contract 明列為方法演進的一部分。

零知識證明（Zero-Knowledge Proofs, ZKP）與 ZKML 提供另一種方向：使證明者能證明某個計算符合規則，而不揭露私有輸入。相關研究已嘗試整合 FL、DP 與 ZKP，以驗證本地訓練或模型更新的合法性。例如 Shakeb 等人提出的 \emph{Zero-Knowledge AI: Enhancing Data Privacy in Federated Learning Models} 將 TinyViT、DP、zk-SNARKs 與 client selection 整合為 ZK-FedTransformer++，並以 RSNA Breast Cancer Detection 醫療影像資料集展示 91.2\% accuracy 與隱私洩漏降低效果 \cite{shakeb2025}。相較於這類整體框架，本研究更聚焦於 \textbf{VDP 更新步驟本身的可審計性}。換言之，本文不宣稱已將完整 FL 本地訓練、反向傳播與 FedAvg 全部寫入同一個 ZKML 電路，而是驗證 DP 更新中的核心條件是否能轉換為可被 ZKML 檢查的約束條件，並將驗證結果接回聚合決策。

\subsection{與相關 ZK-FL 研究之比較}

Shakeb 等人的研究與本文題目相近，皆關注 ZK 技術如何提升 FL 場景中的資料隱私與可信度。然而，兩者的切入點不同。該研究較偏向從醫療影像應用出發，提出整合 TinyViT、DP、zk-SNARKs 與 client selection 的完整 ZK-FL 架構；本文則進一步把 DP 更新中的裁剪與雜訊關係拆解成可實作、可量測、可拒絕篡改案例的 ZKML 約束條件。換句話說，若將 ZK-FL 比喻為替聯邦學習流程加上「防偽封條」，Shakeb 等人的研究說明防偽封條能提升整體信任，而本文實作並測量的是「封條檢查項目」本身：更新是否真的被裁剪、雜訊是否真的被加到更新上，以及不符合規則的 client 是否會被排除。

% (三) 研究方法
\section{研究方法}

\subsection{問題形式化}

\subsubsection{聯邦學習設定}

設有 $K$ 個客戶端，每個客戶端 $k$ 擁有本地資料 $D_k$。第 $t$ 輪時，伺服器持有全域模型參數 $w_t$，客戶端本地訓練後得到 $w_{t,k}$，其更新量定義為
\[
\Delta w_{t,k} = w_{t,k} - w_t.
\]
在一般 FedAvg 中，伺服器對客戶端更新做加權平均並更新全域模型：
\[
w_{t+1} = w_t + \sum_{k=1}^{K} \alpha_k \Delta w_{t,k},
\]
其中 $\alpha_k$ 通常與客戶端資料量成比例。

\subsubsection{差分隱私更新}

差分隱私更新先對 $\Delta w_{t,k}$ 進行裁剪，使其 L2 範數不超過指定界線 $C$：
\[
\Delta w^{clip}_{t,k} =
\Delta w_{t,k} \cdot \min\left(1, \frac{C}{\|\Delta w_{t,k}\|_2}\right).
\]
接著加入高斯雜訊：
\[
\widetilde{\Delta w}_{t,k}
= \Delta w^{clip}_{t,k} + z_{t,k},
\quad
z_{t,k} \sim \mathcal{N}(0, \sigma^2 C^2 I).
\]
本研究中的 $C$ 對應 \texttt{clip\_norm}，$\sigma$ 對應 \texttt{noise\_multiplier}。

\subsubsection{可驗證差分隱私約束條件}

為了讓 DP 更新可被 ZKML 審計，本文將浮點更新轉換為 fixed-point integer witness。給定 scale $s$，定義：
\[
q_{clip} = \mathrm{round}(s \cdot \Delta w^{clip}),
\quad
q_{noise} = \mathrm{round}(s \cdot z),
\quad
q_{noisy} = q_{clip} + q_{noise}.
\]
本文採用標準化見證，因此不直接要求
\[
q_{noisy} = \mathrm{round}(s(\Delta w^{clip}+z)),
\]
因為實驗顯示 $q(a+b)$ 與 $q(a)+q(b)$ 可能存在 1 個量化單位的捨入落差。推薦約束條件包含：

\[
\sum_i q_{clip,i}^2 \leq (Cs)^2 + \lambda,
\]
以及
\[
q_{noisy,i} = q_{clip,i} + q_{noise,i}, \quad \forall i.
\]
其中 $\lambda$ 為容差，用來吸收誠實案例的量化邊界誤差。本研究推薦設定為 $s=10000$、$C=1.0$、\texttt{noise\_multiplier}$=0.08$、\texttt{slack\_ppm}$=4201$，對應 $\lambda=420100$。

\subsection{系統流程與實作方法}

本節依照計畫書的 S0/S1/S2 結構介紹方法流程。整體流程先建立可比較基準實驗，再將 DP 更新形式化為可驗證約束條件，最後以驗證後聚合將驗證結果接回 FL。

此設計對齊原先計畫書中的三階段目標：S0 檢查聯邦學習在資料與模型設定下是否能穩定收斂；S1 檢查加入 DP 後 accuracy 與隱私保護之間的權衡；S2 則檢查 ZK 驗證是否能在可接受成本下提升系統可信度。原計畫書列出的主要量化指標包含 accuracy、proving time、verification time、proof size、peak memory、round time 與 communication overhead；本文已在 16 個資料集、CoverType 大型資料 scaling，以及 Iris/Wine/Digits/CoverType VDP/ZK 實驗中對應呈現 accuracy、training time、proof size、proving time、verification time、circuit rows、peak RSS 與 application-layer communication payload。

\subsubsection{S0：聯邦學習基準實驗}

S0 使用 FedAvg 建立聯邦學習基準。資料先切成 3 個客戶端，各客戶端本地訓練後將模型更新交由伺服器聚合。此基準實驗的目的不是提供隱私保證，而是確認資料與模型設定下 FL 是否能穩定提升準確率。其限制是無法檢查客戶端是否誠實產生更新。

\subsubsection{S1：加入差分隱私的聯邦學習}

S1 在客戶端更新中加入裁剪與雜訊注入。每個客戶端先產生 $\Delta w$，接著裁剪至範數上限以限制敏感度，再加入以種子產生的可重現雜訊。使用可重現雜訊的理由是：若雜訊完全不可重現，後續便無法驗證其是否依規則生成或套用。因此，這一步是從 DP 基準實驗走向 VDP 的必要前置。

\subsubsection{S2：ZKML 可審計 VDP}

S2 將 DP 更新中的兩個核心條件轉換為 ZKML 可驗證形式。第一是裁剪上限，第二是加性雜訊關係。量化約束分析顯示，直接將浮點條件搬進整數約束條件會造成誠實案例誤判，因此後續引入標準化見證並固定推薦約束條件設定。Constraint artifact 單元將公開輸入、見證與檢查結果匯出為 JSON 成果檔；EZKL integration 單元進一步以 EZKL Python API 對小型 ONNX 檢查模型進行實際證明與驗證；proof-gated aggregation 與 end-to-end round 單元則將驗證結果接回聚合。

\subsection{實驗設定}

\subsubsection{主要資料集}

主要資料集為 UCI Adult Income，用於建立主線 FL、DP、VDP 與 ZKML 實驗。資料經前處理、標準化與 train/test split 後，訓練資料切為 $K=3$ 個客戶端。模型採用小型線性模型，以降低 ZKML 映射與 proof 成本。

\subsubsection{額外資料集}

為檢查方法是否只對 Adult Income 有效，本研究額外使用 11 個表格型二元分類資料集進行 FL/DP 基準重複實驗：Breast Cancer Wisconsin、Pima Diabetes、German Credit、Banknote Authentication、Spambase、Tic-Tac-Toe、Titanic、ILPD、PC4、Blood Transfusion 與 KC2。這些資料集涵蓋醫療、信用、軟體缺陷、垃圾郵件、乘客生還與其他二元分類任務。

此外，為測試方法是否能擴展到非二元分類，本研究新增 Iris、Wine 與 Digits 三個多類別資料集。Iris 與 Wine 各包含 3 個類別，Digits 則包含 10 個手寫數字類別。此實驗將模型輸出層從單一 sigmoid logit 改為每個類別一個 logit，損失函數從二元交叉熵改為交叉熵損失，並使用分層方式切分客戶端資料，以降低小型資料集中類別分布不均的影響。

\subsubsection{超參數與評估方式}

主線設定包含 $K=3$ 個客戶端、5 輪聯邦學習、本地訓練週期為 1、\texttt{clip\_norm}$=1.0$、\texttt{noise\_multiplier}$=0.08$。多資料集實驗使用 3 個隨機種子：42、52、62。評估指標包含最終準確率、最佳準確率、DP/FL 保留率，以及證明/檢查是否通過。DP/FL 保留率定義為：
\[
\mathrm{Retention} = \frac{\mathrm{Accuracy}_{DP}}{\mathrm{Accuracy}_{FL}}.
\]
本文以 90\% 保留率作為基準層級的有效性門檻。

\subsection{技術可行性與風險控制}

為回應 ZKML 成本可能被低估的風險，本文不再只使用「可接受成本」的定性描述，而以 15、42、650 維完整更新建立量化基準。三個維度的平均 proving time 分別為 0.100、0.154、0.586 秒，peak RSS 為 410.0、412.5、426.0 MiB，proving key 為 0.89、1.57、25.18 MB。從 15 到 650 維時，circuit rows 由 138 增至 5851，proving key 增加約 28.4 倍，顯示模型擴展風險即使在目前結果可執行時仍不能忽略。

本專題另設定工程風險門檻；此門檻用於控制大專專題資源，不是通用 ZKML 標準。綠色範圍為 proving time 不超過 10 秒、peak RSS 不超過 2 GiB、單一 proving artifact 不超過 256 MiB，可納入重複實驗。若 proving time 為 10--60 秒、RSS 為 2--8 GiB 或 artifact 為 256 MiB--1 GiB，列為黃色範圍，優先降低維度或拆分 constraint proof。超過 60 秒、8 GiB 或 1 GiB 時列為紅色範圍，不納入本文的實務可行性主張。完整 local training circuit 與深度模型目前沒有量測，因此直接列為未來工作。

\subsection{Privacy accounting 的觀察者與隨機性假設}

本文採用 R\'enyi Differential Privacy（RDP）追蹤 Gaussian mechanism 的 sequential composition \cite{mironov2017}。目前每個 client 每輪直接釋出一個 clipping 後更新，client participation 為 $q=1$，因此沒有 subsampling amplification。若 clipping bound 為 $C$、raw noise standard deviation 為 $mC$，則保守 replace-one adjacency 的 sensitivity 為 $2C$，effective noise multiplier 為 $\sigma_{eff}=m/2$。經過 $T$ 輪後：

\[
\epsilon_{RDP}(\alpha)
= \frac{T\alpha}{2\sigma_{eff}^{2}},
\qquad
\epsilon(\delta)
= \min_{\alpha>1}\left[
\epsilon_{RDP}(\alpha)+\frac{\log(1/\delta)}{\alpha-1}
\right].
\]

此 accountant 是 client-level，而不是 record-level DP-SGD accountant。更重要的是，有限 $\epsilon$ 的前提是 noise 對觀察者保持秘密且確實由獨立 Gaussian randomness 產生。目前 artifact 卻把 deterministic \texttt{noise\_seed} 放入 public inputs；verifier 可由 seed 重建 $q_{noise}$，再以 $q_{noisy}-q_{noise}$ 還原 $q_{clip}$。因此，現行 verifier view 的 privacy budget 必須記為 $\epsilon=\infty$。本文仍計算秘密 Gaussian noise 的條件式結果，用於判斷未來修正後可能面臨的 utility trade-off，但不把該數字誤列為目前系統保證。

完整分割的 peak RSS 約為 715--716 MiB。總 accuracy gap 為 0.083091，其中 clipping-only gap 為 0.019257，加入 noise 後額外 gap 為 0.063834；此為 control-based 差距分解，不宣稱一般性的因果比例。CoverType 線性模型的完整更新為 385 維；actual EZKL honest case 通過，prove/verify 為 0.305527/0.039568 秒、proof 12,293 bytes、peak RSS 430.2 MiB。Tampered $q_{noisy}+1$ 的 proof 可驗證算術輸出，但 relation check 失敗而被拒絕。這表示大型樣本可由現有訓練原型處理，且其更新可接入 S2；但 constraint-only proof 並未包含整個 local training trace，calibration 的大型 lookup input 警告亦保留為量化與工具鏈風險。

\subsection{Non-IID 與 client scaling}

為移除 K=3、stratified IID 的單一設定限制，本研究固定 CoverType 100,000 筆 training subset，比較 K=3/10 與 IID、Dirichlet $\alpha=0.5/0.1$；每個條件使用 5 seeds，FL、clipping-only、DP-update 共完成 90 runs。K=10 IID、$\alpha=0.5$、$\alpha=0.1$ 的 DP/FL retention 分別為 0.962019、0.921883、0.834961；K=3 的三者則為 0.888716、0.848033、0.762431。六個條件均可執行，但高度 non-IID 的效用與 seed variation 明顯惡化，因此結果支持 client/partition 可執行性，而不支持所有條件皆能維持 90\% retention。

\subsection{多輪 proof-gated threat matrix}

本研究再以 CoverType K=10、Dirichlet $\alpha=0.1$、3 rounds、20\% attackers 比較 relation tamper、clip bypass、replay、zero-noise 與 bounded sign-flip；3 seeds 共完成 48 條 trajectories 與 1,440 次 client 決策。這些決策重用前期 actual EZKL 的 verified-artifact/check contract，屬於 policy simulation，並非逐更新產生 1,440 份 actual proofs。Current proof+clip+relation gate 對 relation tamper 與 clip bypass 的惡意接受率皆為 0\%，但對 replay 與 zero-noise 皆為 100\%。加入 client/round/model binding、replay protection 與 noise-generation policy 後，後兩者降為 0\%。然而 bounded sign-flip 在 current 與 strengthened policy 下仍為 100\%，且 final accuracy 相對 clean trajectory 僅 0.179797；這證明 update-level VDP gate 不能被解讀為完整 training provenance 或任意 poisoning defense。拒絕兩個最大 non-IID clients 時，部分 strengthened trajectories 的 clean retention 為 0.585848，亦顯示安全拒絕與 availability/utility 的取捨。

\subsection{實驗完整性、統計與可重現性稽核}

本研究另直接讀取 CoverType large-data scaling--27 raw CSV 檢查 expected rows、primary-key uniqueness 與 seed pairing；27/27 large-scaling runs、90/90 non-IID runs、48/48 threat trajectories 與 1,440/1,440 decisions 全部齊全。33 組 accuracy comparisons 以 seed 為分析單位，報告 paired difference、Student-$t$ 95\% CI、paired Cohen $d_z$、two-sided exact sign-flip permutation $p$ 與 family-level Holm correction。由於 $n=3$ 的最小 two-sided exact $p=0.25$，$n=5$ 的最小 $p=0.0625$，所有 Holm-adjusted $p$ 皆未低於 0.05。因此本文不宣稱 accuracy 差異具有統計顯著性，而將其定位為描述性 effect、範圍與工程可行性證據。精確 Python/OS/package versions 與核心 scripts/results SHA-256 亦一併保存。

\subsection{Context-bound hidden-randomness reference protocol}

為將 replay、context swap 與 zero-noise 缺口轉成可 circuit 化的精確規格，本研究建立 commit-before-challenge state machine。Client 在 server challenge 前先承諾 clipped update，且於 rounds 前註冊不可替換的 randomness commitment；server 對每個 commitment 只發出一次 challenge。Hidden seed 綁定 client、round、model hash、nonce、update commitment 與 challenge，public statement 不包含 client secret、derived seed 或 $q_{noise}$。Reference evaluator 對 honest、replay、round/model/challenge swap、zero-noise、secret swap、clip bypass、noisy tamper 與 challenge reissue 共 10 cases 達成 10/10 預期決策。

此結果是 intended circuit relation 的 executable oracle，而非 actual ZK proof。Host reference 使用 HMAC-SHA256、SHAKE256 與 centered-binomial sampler；投稿版仍須選定 circuit-friendly primitives，對 exact quantized sampler 建立 DP theorem/accountant，並產生真正多輪 proofs。因此本節的貢獻是消除 protocol ambiguity 與建立 regression contract，不宣稱已修復 finite-epsilon verifiable DP。

\subsection{綜合討論}

本研究的主要觀察可分為九層。第一，FL 基準與 noise-injection utility prototype 顯示，在多數表格型二元分類資料集上，加入裁剪與低強度雜訊後，模型仍可維持接近 FL 基準的準確率；新增的非二元多類別實驗亦顯示 Iris、Wine 與 Digits 均維持 90\% 以上保留率。第二，ZKML 約束條件實驗顯示，DP update 中的核心條件可被形式化為可驗證約束條件，並能偵測僅偏移 1 個量化單位的篡改含雜訊更新；Wine 的 42 維、CoverType 的 385 維與 Digits 的 650 維更新顯示此檢查可擴展到 Adult Income 以外的多類別資料集。第三，驗證後聚合顯示，這些檢查可接回 FL 聚合決策，讓伺服器只聚合通過驗證的更新。第四，CoverType 顯示 58 萬筆資料可在約 716 MiB peak RSS 下完成，但完整分割的 DP/FL retention 降至 0.884579，資料量本身不能取代 clipping/noise 調參。第五，K=3/10 與 IID/Dirichlet 矩陣證明原型可在較異質 federation 中執行，但高度 non-IID 會降低 utility。第六，多輪威脅矩陣證明 current gate 的 clip/relation 聲明成立，也揭露 replay、randomness 與 training provenance 邊界。第七，完整性/統計稽核確認 raw matrices 可追溯且配對，也限制小 seed 數的推論強度。第八，context-bound reference protocol 將 hidden randomness 與 freshness 轉成 executable circuit contract。第九，privacy accountant 顯示 auditability 與 formal privacy 不能混為一談：public seed 讓現行 privacy budget 為 infinity，而有限 epsilon 所需 noise 又造成明顯 utility 損失。

從具體結果推廣到一般結論的角度看，Adult Income 上的驗證後聚合結果是具體案例，而共 16 個資料集上的 FL/DP 實驗支撐較一般性的說法：目前 DP 更新原型在多種分類任務與大型樣本設定上具備可執行性。不過，banknote、blood\_transfusion 與 CoverType 完整分割的未達標結果也提醒我們，DP 參數不能無條件固定。資料維度、更新幅度、每輪本地最佳化步數與基準穩定性都可能改變相同 clipping/noise 設定的相對干擾。

\subsection{限制與未來工作}

本研究仍有幾項限制。第一，目前 ZKML 實際驗證的是 VDP 核心約束條件，而不是完整的本地訓練、反向傳播與 FedAvg 聚合單一大型電路；bounded sign-flip 結果具體證明此邊界。第二，雖已完成 client-level RDP accountant，但 public deterministic seed 使現行機制不具有限 privacy budget；context-bound randomness protocol 只完成 hidden-seed/context reference semantics，尚未在電路內驗證 exact noise distribution。第三，本文已在 15、42、385、650 維更新上量測 actual proof，並以 CoverType 補上大型樣本規模，但仍限於線性模型；RSS polling 不等同硬體層級 profiler，payload 估計也不含實際網路 framing。第四，non-IID client scaling 雖已完成 K=10、Dirichlet non-IID 與 5 seeds，仍不足以代表 production federation；其餘多數跨資料集實驗只有 3 seeds。第五，context/replay/noise-generation contract 尚未綁入 actual ZK circuit，selective abort、collusion 與 registration authenticity 亦待形式化。

未來工作的最高優先順序是把 context-bound randomness protocol contract 轉成 actual verifiable-randomness circuit：選定 circuit-friendly PRF/commitment 與 integer sampler、證明 exact sampler 的 privacy guarantee，並讓 accountant 直接讀取同一組 parameters。其次，採用 FedScale 等具 natural client partition 與統一 protocol 的 benchmark \cite{lai2022fedscale}，在 10/50/100 clients 上產生真正多輪 proofs，量測 latency、throughput、memory、proof/key size 與 payload。最後，以 local-training proof 或 robust aggregation 處理 bounded poisoning，並透過 power analysis 規劃 utility experiments。

\subsection{結論}

本文依據 VDP-FL 計畫完成了從 FL 基準、noise-injection utility prototype 到 ZKML 可審計 DP-update 原型的完整實驗鏈。核心主張是：\textbf{DP update 中的裁剪與雜訊加性關係可被轉換為 ZKML 可驗證約束，並控制聯邦學習聚合；但正式 verifiable DP 與完整訓練正確性還必須證明 noise 的秘密性、不可預測性、分布正確性、context freshness 與 training provenance。}實驗證據包含誠實／篡改 constraint cases、actual EZKL proof、proof-gated round、16 個資料集、581,012 筆 CoverType、K=3/10 IID/Dirichlet 的 90 runs、48 條多輪 threat trajectories、15/42/385/650 維 actual proof、45 組 privacy--utility runs、33 組 paired audit，以及 10/10 context/randomness reference threats。$\epsilon=\infty$、小 seed 數、replay/zero-noise 與 bounded poisoning 結果不是被隱藏的失敗，而是精確界定系統尚缺哪些元件的重要研究發現。context-bound randomness protocol 進一步把 hidden randomness 與 context freshness 轉成可 circuit 化 contract，但未冒充 actual proof。整體而言，本研究完成的是「將 DP update 作為 ZKML 可審計約束」的原型、風險實證與投稿版方法規格。
